# 单体审查终稿复盘

本复盘来自一次经审查者修正并最终确认的单体审查意见，用于校正skill的覆盖、判断和表达习惯。

## 差异结果

- AI原稿9条，终稿18条；6条保留但压缩措辞，3条删除，12条新增。
- 删除项包括两类偏文件管理的图签/目录问题，以及一条只凭局部门扇符号形成的开启方向判断。
- 新增项覆盖屋面板厚度、防水层数、消防平面参数、儿童活动场所、太阳能系统、剖面表达、露台防护、楼梯和墙身详图索引、重复编号、栏杆高度及防水收口。
- 原稿18张证据图支撑9条意见；终稿20张支撑18条意见，说明证据应精准而非堆叠。单一位置通常一张，跨图矛盾才需要多张。

## 固化规则

1. 不得在设计说明和少量平面发现问题后停止；每张图纸必须关闭覆盖状态。
2. 正式意见定位优先写图号和图名，PDF页码只作为证据辅助位置。
3. 文字采用“明确事实—适用要求或内部矛盾—具体修改动作”，不扩写证据无法支持的推测。
4. 图纸内部矛盾、索引编号和表达完整性问题可以受控填写 `法规条文：无`；技术阈值、强制性和政策结论必须引用规范。
5. 图形方向或符号语义未闭合时不得定案，降级为 `needs_review`。
6. 只接受既定12类意见类型；终稿中的偶发文字笔误不形成新枚举。
7. 单体v1.2及v1.3报告默认使用 `建筑单体施工图内审意见` 及确认后的章节样式。

## 第二次终稿复盘：匿名体育馆单体

一次体育馆单体复盘对比了首次技术审查、补充意见整理稿和审查者终稿。首次技术审查只有4条，终稿为21条；终稿中仅2条可追溯到首次审查的核心问题，另19条来自后续逐图补充。首次工作区虽然把全部图纸标成 `reviewed`，但多项检查只写“已提供无障碍专篇”“防水专篇和大样已提供”“看台大样已提供”或“大样覆盖完整”，导致表面覆盖完整而实质漏审。

本次复盘固化以下经验：

1. 图纸覆盖率不是 `review_status` 的行数统计。每张图纸必须由图号/图名、该图事实和实质检查项共同闭环。
2. 无障碍出入口、无障碍电梯和卫生间不能用“已有专篇”关闭；应分别核对平台、通行与提示、服务设施及详图参数。
3. 防水与屋面不能用“已有防水专篇/墙身大样”关闭；应核对坡向、雨水口或地漏、滴水、上翻、收头及材料层次。
4. 楼梯、栏杆和看台不能用“已有大样”关闭；应核对净宽净高、防护高度与荷载、看台视线和索引闭合。
5. 目录和缺图问题必须核对目录、PDF实际页及图签。一次合并列出多张疑似缺图的意见，终稿只保留了能够确认的一张，说明不确定范围必须留在 `needs_review`。
6. 一条意见只保留一个根因和整改动作。适用条件未闭合的消防或其他技术判断不得进入 `verified`。

## 第三次终稿复盘：匿名中学生活综合楼总图与单体

一次中学生活综合楼复盘对比了AI生成的总图、单体报告和审查者复核稿。AI只提交3条，复核稿有24条；3条均能直接对应，但设计说明、总图无障碍流线、宿舍垃圾间与隔声、无障碍入口、电梯、屋面光伏安全、窗台排水和女儿墙泛水等主题没有进入AI报告。

本次漏审不是图纸未清点，也不是3条意见证据不足。根因是每张图纸只建立一个检查项，且验证器允许用任意数字证明“存在客观事实”。墙身大样记录“300mm、500mm、600mm”等尺寸后即判定符合，却没有核对这些尺寸是否与窗台排水或泛水构造有关。旧回归样例还曾用同一句“控制尺寸1200mm”关闭屋面、剖面、楼梯和墙身大样，等于把缺陷固化为通过条件。

固化以下经验：

1. 证据完整不等于发现完整。每张图至少一个检查只能证明表面覆盖，不能证明本图所有适用主题已经审查。
2. 从v1.3起，图纸按族关闭全部 `coverage_topic`，并记录 `review_item_id` 和匹配的 `evidence_class`。无关尺寸不得关闭其他主题。
3. 宿舍、饮食、学校、停车、电梯、光伏等功能事实必须展开主题包。专项已路由但主题未逐项形成结论时，不得生成Word。
4. 总图说明、单体说明、专项、材料表和图签之间增加项目身份与范围一致性扫描，重点核对项目名称、功能、地下室、电梯、看台和规范版本。
5. 强制/一般技术问题、设计深度矛盾和优化建议分三次发现；保守过滤只能降级为 `needs_review`，不得把未闭合的高风险主题静默删除。
6. 审查者意见不是无条件真值。复盘时仍应合并同一根因、拆开混合根因，并对门扇方向、缺失表达和优化建议重新闭合图形及条文证据。

## 第四次过程复盘：匿名生产值班用房假完成

一次生产值班用房审查生成了84条检查记录和3条正式意见，并把23张图纸全部标成 `reviewed`。复盘发现，多数检查由项目脚本直接赋值为“符合”，规范快照的 `used_standards` 为空，绝大部分技术闭环没有条文、要求和比较过程。审查者确认该项目此前有18条实际意见，而这3条基本不是真正有效意见。

该案例尚未取得审查者18条终稿的文件和逐条映射，因此不能作为已批准金标准；但它已经证明旧流程存在可重复的假完成路径：程序填充结论、程序填充验证通过、主题壳代替技术规则、Word和视觉QA通过后误认为专业审查完成。

由此固化：

1. 新检查必须默认 `unreviewed/需核验`，程序不得填写符合、图纸已审或人工验证通过。
2. 技术符合与不符合都必须关联可执行B类规则，并记录图纸事实、比较过程和必要计算。
3. 图纸主题关闭之外，还必须关闭项目画像为本图纸触发的全部原子规则。
4. 完成度审计绑定所有输入哈希，审计后任何台账变化都会失效。
5. 发布能力只能由审查者确认的金标准盲测证明；Word生成和版面QA不证明发现能力。
